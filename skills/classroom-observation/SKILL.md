# 听评课记录 Skill · v2.0

## 一句话启动

打开就说「**记听课**」或「**汇总评课**」，不用先描述格式。

## 核心心智模型

**模型1：事实与评价分离**——听课记录的第一部分是"发生了什么"（环节/师生活动/时间分配的实录），第二部分才是"怎么看"（亮点/建议/评分）。混写实录与评价是听课记录失效的头号原因——争议时谁也回不到事实。依据：课堂观察的客观记录传统（LICC范式）；证据本位评课理念。应用：记录模板强制先实录后评价，评价条目必须能指回实录中的事实。局限：教学直觉丰富的老教师可压缩实录，但正式评课记录保留全结构。

**模型2：建议必须可操作**——"要加强师生互动"是无效建议，"提问后等5秒再点名"是有效建议。每条建议落到"下一个具体动作"。依据：教师反馈研究的可操作性原则；评课建议被采纳率与具体度的关系。应用：输出前逐条自检——这条建议老师明天上课能用吗？不能用的改写到能。局限：方向性大问题（课程设计层面）允许陈述为"议题"，标注需另约时间深谈。

**模型3：多源记录并列不裁决**——多人听同一节课，意见分歧是常态也是财富；汇总时同一维度不同意见并列呈现，裁决权在教研组与授课教师本人。依据：评课的民主专业传统；AI不当裁判的边界。应用：汇总表按维度归并，分歧处标"存在分歧"并列两说。局限：触及师德/安全底线的记录直接上报，不走并列呈现。

## 决策启发式

1. **先实录后评价，顺序不反**——没有实录支撑的评分是印象分。
2. **亮点至少两条、建议不超过三条**——全是优点的评课是敷衍，建议超过三条是压垮。
3. **每条建议配一个可观察的验证点**——"下次听课看X是否出现"，形成闭环。
4. **时间分配记到分钟**——时间结构是课堂设计的X光片。
5. **评课稿先给授课教师看**——反馈顺序：授课教师自评→听课人反馈→汇总归档，不让老师从别人嘴里第一次听到自己的评课结果。

## 输出协议

```
📋 听课记录
授课教师：______  科目：______  班级：______
课题：______  听课人：______  日期：______

一、课堂实录（教学环节、师生活动、时间分配——只记事实）
二、亮点（至少2条，每条指回实录事实）
三、建议（不超过3条，每条落到可操作动作）
四、评分（满分5分：教学目标/教学内容/教学方法/师生互动/教学效果）
五、总评
```

## 检查点

🔴 **动手前**：确认听课目的（常规检查/教研打磨/新教师考核）——目的不同，记录侧重点不同。

🔴 **中途**：实录与评价严格分栏——写作过程中混入的评语移到评价区。

🔴 **交付前**：建议逐条过"可操作自检"——明天能用吗？不能用的改写。

## 输出规范

- 听课记录按"课堂实录（环节/师生活动/时间）→ 亮点 → 建议 → 分项评分 → 总评"五段输出，事实与评价分开写。
- 多人听课汇总：按维度归并各人记录，同一维度不同意见并列呈现，不擅自裁决。
- 评课建议落到可操作动作（"提问后等5秒"而非"要加强互动"）。

## 失败与异常处理

1. **听课信息不全**：缺授课教师/科目/课题基本信息先补问，不带空字段出记录。
2. **只有分数没有过程**：提醒补课堂实录——无事实依据的评分不生成。
3. **评课意见冲突**：汇总时并列呈现两种意见，标注"存在分歧"，不由AI裁决。
4. **超出范围**：要教学处分处理结论（如考核定性）——转教学处正式流程，听评课记录只提供事实素材。

## 边界与提醒

- 听评课服务于教师成长，不服务于考核排名——评分数据不用于绩效排序（学校另有考核口径的除外）。
- **不替代**：听课人的现场专业判断——AI 整理与结构化，课堂的丰富性只有人在现场能感知。
- **接不住就转**：深度课例研究转 collaborative-teaching-research；化学学科的闭环听评转 chem23-lesson-cycle 体系。

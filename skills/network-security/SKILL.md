# 网络安全管理 Skill · v2.0

## 一句话启动

打开就说「**查网络安全**」，不用先描述格式。示例：「校园网，做一次安全自查」——按等保项出检查清单 + 风险等级 + 整改优先级。

## 核心心智模型

**模型1：纵深防御（洋葱模型）**——安全不是一道门，是一层层皮：边界（防火墙/访客网隔离）→ 终端（杀毒/补丁）→ 账号（口令/权限）→ 数据（备份/加密）。攻破一层还有下一层。依据：等级保护2.0的分层设计思想。应用：自查清单按层组织，任何一层出现"全空"（如全校无人改默认口令）直接标高风险。局限：学校不是军事系统——层层数量适度，投入与风险匹配，重点守数据层。

**模型2：最弱环节在人和流程**——校园安全事件的第一大来源不是黑客，是弱口令、共用账号、明文发送密码、来路不明的U盘。依据：教育行业安全事件通报的共性归因。应用：自查清单里"人"的项（口令策略/账号唯一性/培训记录）权重不低于"设备"的项。局限：人的习惯改变慢，靠制度+提醒双管，不能只靠一次培训。

**模型3：数据敏感性分级**——不是所有数据都值得同等保护：学生隐私（成绩/健康/家庭）> 教职工人事 > 教学资源 > 公开信息。防护投入按级别分配。依据：《个人信息保护法》与教育数据分类分级要求。应用：备份策略、权限设计、泄露应急优先级都按此排序；学生隐私数据"能不采集就不采集，能不留存就少留存"。局限：分级需要学校确认口径，AI按默认分级给方案，最终以学校数据制度为准。

## 决策启发式

1. **默认口令 = 大门敞开**——新设备/新系统上线第一件事改默认口令，这条不过其他都白搭。
2. **备份的三问**：备的是什么（数据清单）、多久备一次（频率）、备到哪（异地/离线）——答不齐就当没有备份。
3. **账号跟人走，不跟岗位走**——共用账号出了事无法追责，一人一号是最便宜的审计手段。
4. **应急卡贴在墙上，不是锁在文件里**——断网/中毒/泄露的第一响应步骤要让值班人员30秒内找到。
5. **真实攻击立即上报，AI退场**——取证和处置是网信/公安的专业，第一时间报属地部门，不在AI里"分析案情"。

## 执行规范

老师说"帮我做网络安全检查 / 出安全制度"即可。缺信息先问：查什么范围（校园网/机房/办公终端）、什么用途（日常自查/等保测评/专项检查）。信息齐了，按需做四样：

1. 安全检查清单：账号口令（弱口令/默认口令/共用账号）、数据备份（频率/异地）、终端防护（杀毒/补丁）、网络边界（防火墙/访客网络隔离）、移动存储管理。
2. 风险评级：每项按 高/中/低 标注，高风险项给立即整改动作，中低风险给限期整改。
3. 制度文件框架：网络安全责任制度、账号权限管理制度、数据备份制度、应急响应预案——各给可填模板。
4. 应急响应卡：断网/中毒/数据泄露三类常见事件的第一响应步骤（谁来做、先做什么、多快上报）。

## 检查点

🔴 **动手前**：确认检查用途（日常自查 vs 等保测评）——口径不同，清单深度差一倍。

🔴 **中途**：学生隐私数据的存储与权限单独成节核查，不混在一般数据项里。

🔴 **交付前**：高风险项是否都给了"立即整改动作"——只标风险不给动作的清单是无效交付。

## 输出规范

- 检查清单按四层（边界/终端/账号/数据）组织，每项带风险等级与整改建议，一表可打。
- 制度模板含填空位与责任人签字位，不留"原则上""相关部门"这类虚词。
- 应急响应卡一页三卡（断网/中毒/泄露），每卡不超过5步，第一步永远是"谁做什么"。

## 失败与异常处理

1. **查出一堆高风险没资源整改**：出"先堵三个最大的洞"排序——默认口令/备份缺失/隐私数据裸奔，这三项花小钱办大事，其余限期。
2. **教师抵触账号实名（嫌麻烦）**：给"一人一号不限制装什么，只要求出事能找到人"的说明——审计不是监控。
3. **外包/租赁系统数据归属不清**：合同层问题列清单转学校法务与供应商 renegotiate，AI 只标风险不改合同。
4. **真实安全事件发生**：立即转属地网信/公安上报流程，本技能只保留"事发前的检查记录"供参考，不参与处置。

## 边界与提醒

- 本技能管制度和自查清单，不替代专业安全设备和渗透测试。
- 涉及真实攻击事件、需要取证的，立即报属地网信/公安，AI 不介入处置。
- 学生隐私数据（成绩/健康/家庭信息）的存储与权限单独核查——这是校园场景最高风险项。
- **不替代**：专业安全厂商的技术测评——AI 出的是管理侧清单，技术渗透另请专业机构。
- **接不住就转**：设备台账与硬件运维转 it-device-management；学生数据系统的权限设计转信息中心。

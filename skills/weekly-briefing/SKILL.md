# 云端周报 v1.0

> 每周一份，把这一周干的事、下周要干的事说清楚。

## 执行规范

老师说"帮我做周报"即可。缺信息先问：本周各部门做了什么、下周计划、有没有需要协调的事。信息齐了，做四段：

1. 本周工作汇总：按部门/事项列，干了什么、进展到哪。
2. 亮点与数据：有数据的带数据，没数据的写进展。
3. 下周计划：明确、可核查。
4. 需协调事项：卡在哪、需要谁支持。

## 核心心智模型

**模型1：「周报是协调工具，不是成绩汇报单」**
- 定义：周报四段（本周工作/亮点数据/下周计划/需协调事项）的核心价值在第四段——"卡在哪、需要谁支持"是跨部门协作的接口；只报喜不报卡的周报，读者读完什么也不用做。
- 依据：本技能四段结构设计；管理周报的协调功能定位。
- 应用：需协调事项为空时自查"真的没有卡点，还是不好意思写"——前者可空，后者必写。
- 局限：对上汇报与内部协调两种读者——对外发版可裁剪协调段，内部版必留。

**模型2：「有数据的带数据，没数据的写进展」**
- 定义：量化优先但不容忍编数——"完成80%"要有依据（完成件数/计划件数），无依据时写里程碑事实（"已通过验收"）而不是估个百分比。
- 依据：本技能执行规范"有数据的带数据，没数据的写进展"。
- 应用：每条亮点数据附口径（统计范围/时间）；下周计划逐条可核查（有完成标志）。
- 局限：刚起步的工作没有可量化进展——写"下一步动作+时间点"，不写百分比。

**模型3：「真实是周报的信用底线」**
- 定义：不夸大成绩、不掩盖问题——周报的读者（校长/各部门）会交叉验证，一次失真，此后每期周报的可信度打折。
- 依据：本技能边界"周报数据要真"。
- 应用：问题如实写（滞后事项标红），成绩与问题比例不失真；敏感事项（人事/财务/学生隐私）不上周报。
- 局限：有些问题不宜书面化——口头专报渠道处理，周报不背所有沟通职能。

## 决策启发式

| # | 触发情况 | 动作 |
|---|---|---|
| H1 | 没给各部门素材 | 给素材采集模板（四段×各部门一行），收齐再写 |
| H2 | 部门素材是流水账 | 按四段重排——干成什么/数据/下周/卡点，原文细节保留在附件 |
| H3 | 数据来源拿不准 | 标注"待核"——不带存疑数据出正式版 |
| H4 | 敏感信息混入 | 剔除并提示线下专报——未公开人事/财务/学生信息不上周报 |
| H5 | 要"写好看点" | 拒绝夸大——可以更好排版、更清晰表达，不虚构进展 |

## 检查点

🔴 **动手前**：本周各部门素材、下周计划、协调事项三样在手。

🔴 **中途**：四段结构完整；每条数据有口径。

🔴 **交付前**：敏感信息零残留；下周计划逐条可核查。

## 输出规范

- 四段结构：本周工作汇总（按部门/事项列进展）/亮点与数据（带口径）/下周计划（可核查）/需协调事项（卡点+所需支持）。
- 篇幅一页；滞后与风险事项标红——排版服务信息，不遮信息。
- 版本头注明期数与统计区间。

## 失败与异常处理

1. **素材不全**：给采集模板收齐再写；紧急时先出"已收部门版"并标注缺报部门。
2. **数据口径打架**（两部门数字不一致）：并列呈现+标注待核——不擅自裁决。
3. **敏感事项**：剔除+提示专报渠道。
4. **超范围**（月报/学期总结）：结构可复用但节奏不同——月报转monthly-report类工具。

## 边界

- **管**：周报四段撰写、素材重排、数据口径标注。
- **不管**：月度/学期总结（另套工具）；各部门内部台账（各部门自管）。
- **不替代**：各部门负责人对素材真实性的签字责任——AI编排，内容责任在部门。
- **接不住就转**：会议决议的落实跟踪转meeting-minutes待办机制。

## 分工说明

与meeting-minutes分工：纪要管"会上定了什么"，周报管"这周干成了什么"；两者共享待办字段的口径。

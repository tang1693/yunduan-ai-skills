# 学生请假管理 Skill · v1.0

## 一句话启动

打开就说「**办请假**」，不用先描述格式。

## 核心心智模型

**模型1：「家长知情是请假的成立要件」**
- 定义：学生请假的法律与安全前提是监护人知情——没有家长确认的"请假"只是学生单方告知，不成立；联系不上家长的按异常情形处置（不是不批，是升级处理）。
- 依据：未成年人保护的责任逻辑；本技能执行规范"请假必须家长知情"。
- 应用：申请单的家长确认栏是必填项（电话确认记录亦可）；无家长信息的申请退回补。
- 局限：紧急就医场景先放行后补手续——安全优先于程序，但手续必须补。

**模型2：「销假闭环——账不闭环人不闭环」**
- 定义：请假管理的风险不在"批"，在"回"——销假未记录的学生处于"状态未知"，与未请假缺勤同样危险；每笔请假必须以销假记录收口。
- 依据：本技能台账"销假未记录的按未归校追踪"条款。
- 应用：到期日自动生成销假核对提醒；未销假名单并入student-attendance追踪。
- 局限：长假（病假一个月）的中间状态——按周电话回访记录替代即时销假。

**模型3：「审批权限分级，越级批是失序」**
- 定义：1天内班主任批、3天内年级组长批、3天以上报学生处——分级审批既是秩序也是责任对应；越级批（班主任直接批十天）让制度形同虚设。
- 依据：本技能审批指引三档。
- 应用：申请单按请假天数自动标注应批层级；越权审批提示退回对应层级。
- 局限：紧急情况先斩后奏——放行在先，补审批在24小时内完成。

## 决策启发式

| # | 触发情况 | 动作 |
|---|---|---|
| H1 | 请假五要素缺项（学生/类型/起止/事由/家长确认） | 逐项补问——家长确认缺失退回 |
| H2 | 联系不上家长 | 按异常处置（紧急联系人/年级组/学校应急口径）——不按常规请假走 |
| H3 | 病假无医疗证明 | 3天内可先批后补；超3天补证明再批 |
| H4 | 在校期间临时外出 | 监护人到校接或书面授权，台账单独记——不混入常规请假 |
| H5 | 要查某人请假记录 | 按台账出个人记录——数据仅班主任与学生处可见 |

## 检查点

🔴 **动手前**：五要素齐备；审批层级与天数匹配。

🔴 **中途**：台账逐笔登记（含请假条编号）；销假提醒生成。

🔴 **交付前**：周汇总到人次（不列个人明细）；未销假清单并入追踪提醒。

## 输出规范

- 四件输出：请假申请单（五要素+审批分级签字栏）/审批指引（三档权限+病事假材料要求）/请假台账（日期-学生-类型-天数-销假日期）/出勤统计（周人次+连续请假预警）。
- 连续病假≥2天附"班主任电话回访"提示（关怀非质询）。

## 失败与异常处理

1. **信息不全**：补问五要素；紧急就医先放行后补。
2. **家长无法联系**：升级异常处置流程——安全链条不断。
3. **超长病假**（月级）：按周回访记录+复课证明要求，销假以复课日计。
4. **超范围**（教职工请假）：转attendance-management——两套口径不混。

## 边界

- **管**：请假申请、审批指引、台账与销假、出勤人次统计。
- **不管**：到课追踪与安全核实（转student-attendance）；教职工请假（转attendance-management）。
- **不替代**：审批人的签批决定——AI管流程完整，批不批在人。
- **接不住就转**：未请假缺勤的追踪转 student-attendance。

## 分工说明

与student-attendance分工：本技能管"请假的手续与台账"，那边管"到没到的追踪"——已请假缺勤不触发那边的安全提醒，销假未记录则触发。

## 执行规范

老师说"帮我办学生请假 / 汇总请假"即可。缺信息先问：哪个学生、请假类型（病假/事假/其他）、起止时间、家长是否知情。信息齐了，做四样：

1. 请假申请单：学生 / 班级 / 类型 / 事由 / 起止时间（具体到节次）/ 家长联系方式与确认 / 班主任签批。
2. 审批指引：1天以内班主任批；3天以内年级组长批；3天以上报学生处——病假附医疗证明，事假说明具体事由。
3. 请假台账：日期 / 学生 / 班级 / 类型 / 天数 / 销假日期——**销假未记录的按未归校追踪**。
4. 出勤统计：按班级周汇总请假人次 / 病事假分布 / 连续请假预警（连续2天以上病假建议班主任电话回访）。

## 边界与提醒

- 请假必须家长知情——联系不上家长的高风险情形按异常处置，不按常规请假走。
- 学生在校期间临时外出（如就医）需监护人到校接或书面授权，台账单独记。
- 请假数据涉及学生隐私，统计只到人次，不公开个人明细。

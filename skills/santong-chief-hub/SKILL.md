# 三同工作台·首席教师总入口

> 书稿里那句话是这个技能的魂：**「修改直至通过」可以形成质量关口，也可能形成中心权威。首席教师审核能够阻止未经检验的方案直接进入多校课堂，但不应把异议变成服从。**

## 一句话启动

打开就说「**三同**」。示例：「物理首席，下学期统筹」——AI 按六步流程出学期统筹案；课中说「说课审核」进入审核工作台。

## 首席学期统筹（六步之①②）

29 位首席分三种节奏，统筹逻辑不同：

| 学科 | 同教频次 | 统筹策略 |
|---|---|---|
| 语数英 | **每周 1 节** | 学期一次性排定 18 周主题链（第 1 周定全学期内容主线，每周一次六步循环）；主备按专长分段包干，一学期每人主备 2-3 次 |
| 理化史地道生 | **每月 1 节** | 按单元排 4-5 节；每节完整六步循环，间隔期做上一节的课后双路报告消化 |
| 其他学科 | **每学期 1 节** | 单节精品制：六步全流程 + 观课复盘重点投入，一学期磨透一节 |

统筹输出：学期主线上墙表（周次 × 主题 × 主备 × 说课日 × 同教日）+ 主备分配表（按专长，首席本人也认领一段）。

## 六步流程编排（③④⑤⑥转专技能，本入口管衔接）

1. **定内容**（首席+主讲）→ 本入口出主题链与分配；
2. **分配主备** → 本入口出分配表；
3. **学情修改汇集** → 共同体教师提交「本班修改建议单」（一条建议 = 改哪里 + 依据是什么班情），本入口汇总成修改清单转主备；
4. **主备汇总教案课件** → **转 四维协同备课设计师★5**（产出统一教案 + N 校适配）；
5. **说课审核** → 本入口审核工作台（见下）；
6. **二轮集体备课** → 本入口出议程模板（流程确认 + 课堂细节 + 暗号与技术彩排）→ **转 四维协同授课策划器★4** 出课案。

## 说课审核工作台（六步之⑤——质量关口）

书稿流程图明确：**审核未通过 → 转学科负责人 + 课程调整**。审核台四步：

1. **过五关**（每关一句判定）：目标是否服务育人主线 / 任务是否真让学生动 / 证据设计能否看见学习 / 四维分工是否清楚 / N 校差异是否被尊重而非抹平；
2. **异议处理**（书稿六种风险的防线）：有异议必记录——谁的异议、依据（课标/学情/经验）、处置（采纳/保留意见继续/退回）三列，**不允许「少数服从多数」式沉默**；
3. **审核结论**三档：通过 / 修改后通过（列具体修改点）/ 不通过（转学科负责人）；
4. **留痕**：审核记录（含被否的理由）入版本链——书稿第五种风险就是「只保存通过的版本会遮住争议」，被否方案与理由同样归档。

## 课后双路报告（书稿图10-1 的两条路径）

- **技术路**：平台数据 → 数据报告 → 教学处（转 1+N数据分析★5）；
- **教学路**：辅讲评价 + 学生反思 + 教师反思 → 课堂报告 → 教学案例（本入口出三表模板并归集）；
- **回流闭环**：双路汇合处出「下一轮修改单」——课堂事实推翻已通过方案时，标注「方案回炉」并通知首席。

## 核心心智模型

**模型1：「修改直至通过 = 质量关口 + 中心权威，一体两面」**
- 定义：首席审核能把住"未经验证的方案不进多校课堂"的关，同样也能把共同体变成"以首席为圆心"的服从结构——关口与权威是同一个机制的两面，设计者的任务是放大前者、抑制后者。
- 依据：《云端学校》第十章原文"可以形成质量关口，也可能形成中心权威"；六步流程的异议处理设计。
- 应用：审核台三档结论（通过/修改后通过/不通过）之外永远留第四条路——"保留意见继续"（异议记录在案但方案照走）；被否方案与理由同样归档（不遮争议）。
- 局限：首席的人格与威望会自然压低异议率——匿名建议单是结构补偿，不是信任替代。

**模型2：「课堂事实高于审核结论」**
- 定义：再完善的审核也只是课前推演，多校课堂的真实反应是最终裁判——课堂事实推翻已通过方案时，方案回炉、审核记录追加"撤回"标注，这是书稿写明的撤回机制。
- 依据：书稿图10-1课后双路报告的回流闭环；"审核未通过→课程调整"箭头的反向版本。
- 应用：课后双路报告（技术路→教学处；教学路→案例库）汇合处出"下一轮修改单"；回炉不追究审核人，只修方案。
- 局限：课堂事实的归因也可能错（设备故障≠设计失败）——修改单上区分"设计问题/执行问题/技术问题"三类。

**模型3：「驻地教师的差异是资源不是噪音」**
- 定义：各校学情修改建议（一条建议=改哪里+依据是什么班情）不是对统一教案的干扰，是多校知识进入方案的唯一通道——收不上来修改建议的共同体，只是各校在旁观。
- 依据：书稿"驻地教师只能配合时，多校知识就无法进入方案"；本入口步骤3的修改汇集设计。
- 应用：修改建议单三列（改哪里/依据/提交人）逐条转主备；版本链缺 v2（学情修改版）= 共同体参与被跳过，退回。
- 局限：驻地教师不敢提异议是常态——匿名渠道保底 + 首席在二轮备课现场点名回应每条匿名建议（回应比名字更重要）。

## 决策启发式

| # | 触发情况 | 动作 |
|---|---|---|
| H1 | 审核现场"大家都没意见" | 主动问一句"驻地老师那边本班情况真的没有要调的吗"——不让沉默溜过关 |
| H2 | 主备临时变更（书稿第9期案例重演） | 启用应急改课——共同资源池30分钟重组新脚本，六步顺序不压缩 |
| H3 | 审核三轮不过、首席与主备僵持 | 升级学科负责人仲裁；首席不当独裁者也不当橡皮章 |
| H4 | 学期节奏被考试打断 | 统筹表插空重排，砍内容不砍流程——六步一步不少 |
| H5 | 版本链缺v2（学情修改版） | 退回：共同体参与被跳过了，这份方案只代表主备一个人 |

## 输出规范

- 统筹表：周次 × 主题 × 主备 × 说课日 × 同教日，一页一学期（语数英周节奏/理科月节奏/其他学期节奏三档）。
- 修改建议单：改哪里 / 依据（班情）/ 提交人，一条一行；匿名建议单独编号。
- 审核记录：五关判定 + 异议三列（谁的异议/依据/处置）+ 三档结论 + 签字位，一次说课一页。
- 课堂报告三表：辅讲评价（各班一句）/ 学生反思摘录（匿名）/ 教师反思（云端+驻地各一段）。
- 版本链：v1主备稿→v2学情修改→v3审核后→v4课后回炉（如有），每版留一句"这版改了什么、为什么"。

## 检查点

🔴 **动手前**：学科节奏档（周/月/学期）与主备名单确认；新任首席先走一遍流程导读。

🔴 **中途**：异议必录执行到位——出现"一致通过"字样时先查是不是沉默，再查是不是真一致。

🔴 **交付前**：版本链完整性核对——缺v2退回；审核记录（含被否方案与理由）已入归档。

## 失败与异常处理

1. **主备临时变更**：应急改课（资源池30分钟重组），六步顺序不压缩——砍内容不砍流程。
2. **驻地教师不敢提异议**：改匿名建议单；首席在二轮备课现场逐条点名回应——回应比名字更重要。
3. **审核陷入反复**（三轮不过）：升级学科负责人仲裁，记录双方理由，本入口不当裁判。
4. **课后事实推翻已通过方案**：标"方案回炉"通知首席；修改单区分设计/执行/技术三类问题，不追究审核人。

## 边界

- **管**：学期统筹、主备分配、修改汇集、说课审核工作台、课后双路归集、版本链、共同体周报素材。
- **不管**：教案课件生产（转 四维协同备课设计师）；授课现场执行（转 四维协同授课策划器）；听评课（转 四维联动教研助手）；共同体行政事务（转 collaborative-management）。
- **不替代**：首席的学科判断——五关给结构，判断仍是人的。
- **接不住就转**：跨校数据对比转 1+N数据分析；入驻校对接转 partner-school-coordination。

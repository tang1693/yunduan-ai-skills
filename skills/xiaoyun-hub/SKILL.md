# 小云学堂·数字实验班运营台

> 实验班验证的不是「AI 能不能教知识」，是「AI 时代的学习方式长什么样」——日常任务记录可提供探索线索，仍需结合课堂观察、支持条件和后续独立迁移，不能把数据直接当结论。

## 开始前：最少准备

说明年级、人数、本周时间和实际可用条件。未建数字学生系统也能用：先出教师带领的纸质自学、提问、同伴交流与观察草案；有系统时再核对其真实能力，不要求为使用本方法另建系统。

默认面向教师备课与组织支持，学生接触的材料须经教师核对。文中人数、分组和时长是本校方案示例，按实际情境调整；S级为作者原有自评，不是本轮教师试用结论。引用其他Skill表示可选协作，不代表客户端已经安装或能够自动调用；缺少时在当前对话给可编辑表或步骤，说明未完成部分。

[中文使用卡、完整示例与失败处理](references/中文使用卡.md)。首次先给一小段候选，教师满意再展开；已给材料不重复询问。

## 一句话启动

打开就说「**小云学堂**」。示例：「本周实验班运营」——出周课表编排、20 人进度差异表、月度探索证据框架。

## 上午·AI 自适应七步循环（对接 model-3-2-daily-runbook）

按 3+2 模型每日运行手册执行：诊断 → 定标 → 推送 → 学习 → 追问 → 检测 → 调整。
本运营台管三件事：

1. **节奏编排**：七步里哪些学生走全流程、哪些人跳过定标（连续 3 天达标者进入自主模式，只保留检测环节）；
2. **差异控制**：按课程目标记录每次任务的尝试与支持条件，不按人与人的差值强制追赶；同伴讲解自愿轮换，由教师确认是否适合；
3. **教师位次**：每循环教师的三个必到点——晨间定标抽查 2 人、午后追问旁听 1 组、放学前看全员检测热力图。

## 下午·PBL 高阶时段（对接 高阶能力项目设计师）

- 周一立项（选真实问题：校园节水/给低年级做识字游戏）、周三中期（每组过一次「卡点问诊」）、周五路演（5 分钟展示 + 互评一张表）；
- AI 在下午的角色是「资料员 + 追问者」，不是「代做者」——学生问「帮我做」，AI 回「你打算怎么做？我可以找资料」；
- 4-5 年级的 PBL 主题库按月轮换：校园类 → 家庭类 → 社区类 → 开放类，难度递进。

## 月度·学习方式探索证据（实验班的立项使命）

每月从数据里回答三个问题，一页纸交教研组：

1. **节奏差异**：20 人完成同一目标的用时分布——最大最小差多少？说明什么？
2. **干预效果**：AI 推送的内容哪些被跳过、哪些被反复看？——这是「什么值得推」的证据；
3. **能力迁移**：下午 PBL 里用到的上午所学，学生能不能自己调用？——区分独立完成、提示后完成及延迟迁移；单次调用率不直接等于“真学会”。

这份月报是实验班对外的唯一成绩单——不出分数排名，只出学习方式发现。

## 核心心智模型

**模型1：「实验班验证的是学习方式，不是知识进度」**
- 定义：小云学堂的立项使命是回答"AI时代的小学生该怎么学"——不是提前学知识，不是AI提分。一切编排决策以此为准绳：能产出"学习方式证据"的活动优先，单纯赶进度的活动让位。
- 依据：本技能描述"不是提前学知识，是验证AI时代学习方式"；月度证据三问的制度设计。
- 应用：月度证据三问（节奏差异/干预效果/能力迁移）是实验班唯一对外成绩单——不出分数排名，只出学习方式发现。
- 局限：家长和学校天然会问成绩——用"证据三问+能力迁移数据"回应，不回避也不迎合。

**模型2：「AI管循环，人管人」**
- 定义：上午七步循环（诊断→定标→推送→学习→追问→检测→调整）交给AI跑，但教师每天三个必到点（晨间定标抽查2人/午后追问旁听1组/放学前看全员热力图）不可省——AI管的是流程，教育发生靠人的在场。
- 依据：本技能"教师位次"条款；汤幸初体系"效率层给AI、判断层留给人"的第一性原则。
- 应用：教师必到点写进周课表；掉线日预案启动时教师巡回密度加倍（AI不在，人必须更在）。
- 局限：三个必到点是底线不是上限——新教师前两周建议全时段在场。

**模型3：「先猜后看，防AI拐杖化」**
- 定义：任何AI讲解前，学生必须先给出自己的猜测（口头/书面），猜错不扣分，暂时猜不出时先给一个低门槛提示，仍可求助或暂停——把AI从"答案贩卖机"改造成"猜测验证器"。
- 依据：本技能失败处理第4条；小云学堂"学生依赖AI不动脑"的实际应对。
- 应用：七步循环的"追问"环节和PBL的"资料员AI"都执行此规则；月度证据三问的"干预效果"专门统计跳过率。
- 局限：低成就学生猜测成本高——允许"猜个方向"级别的粗糙猜测，逐步提高精度要求。

## 决策启发式

| # | 触发情况 | 动作 |
|---|---|---|
| H1 | 系统全天故障 | 切换无AI日——纸质七步卡（自定目标/自学/自测/同伴问），记录故障时长供复盘，不停课 |
| H2 | 20人进度两极分化 | 允许上午分层，但下午PBL由教师协商分组——上午可以快慢，下午保留共同交流与个别支持 |
| H3 | "小老师"连续两周没轮上某人 | 查边缘化——进度差异表的处置动作每周复核一次 |
| H4 | 家长质疑"整天玩电脑" | 请来看一次随堂（"AI在追问、孩子在答"的现场）+ 月度证据三问，质疑自然消 |
| H5 | 月报写不出数据支撑的发现 | 不写——只附去标识的任务证据摘要与来源；无数据则写待观察，不上传原始学生数据 |

## 输出规范

- 周课表一页：上午七步循环时间块 + 下午PBL三节点（周一立项/周三中期/周五路演）+ 教师三个必到点。
- 20人进度差异表：去标识代号/本次任务/独立或提示后完成/支持条件/待观察/教师选择，每周更新。
- 月度探索证据一页三问，每问注明数据来源（看板哪个模块）+ 去标识证据摘要（原始记录留校内）。
- 家长版月报：只写"孩子本月学会自己做了什么"，零对比数据。

## 检查点

🔴 **动手前**：按实际条件选择系统模式或长期人工模式：系统模式先确认可用能力；无系统用纸质任务与观察表，临时掉线可用无AI日预案。

🔴 **中途**：进度差异处置每周复核——小老师任务是教学相长不是廉价劳动力，轮不到的要查原因。

🔴 **交付前**：月度证据三问逐问核对数据出处——没有原始数据支撑的发现从月报删除。

## 失败与异常处理

1. **系统故障全天**：无AI日预案（纸质七步卡+教师巡回加密），运营台记录故障时长——故障本身也是"AI依赖度"的实验数据。
2. **学生集体绕过"先猜后看"**：降低表达门槛，允许口头、画图或先看提示再尝试，不以积分或解锁剥夺求助机会；同时检查推送内容是否太难导致猜测无门。
3. **PBL下午沦为"AI代做"**：AI角色卡死在"资料员+追问者"——学生说"帮我做"，AI回"你打算怎么做？我可以找资料"；路演时教师抽问组内任意成员验证参与度。
4. **两极分化超一周阈值**：教师先了解任务难度和支持条件，再提供可选择的小步任务；不按进度差强制安排“小老师”。

## 边界

- **管**：周编排、进度差异处置、月度探索证据、无AI日预案。
- **不管**：数字学生系统本身运维（转信息中心）；PBL课程内容设计（转 高阶能力项目设计师）。
- **不替代**：教师的三个必到点——AI管循环，人管人。
- **接不住就转**：单个学生学习诊断转 追问式诊断引擎；心理关切联系班主任及本校有资质的人工支持，不让AI诊断或保存谈话原文；思辨课/大问题卡（周五下午或晨会 15 分钟一题）转 fuyao-conundrum·**小云版层**（4-5 年级适配：圈选+画写作答、白话庄子封面，母题映射表已对齐）。

## 分工说明

与 model-3-2-daily-runbook（3+2每日运行手册）的关系：runbook管七步循环怎么跑，本运营台管20人怎么编组盯进度；与 xiaokun-bridge（六年级衔接）分学段而治。

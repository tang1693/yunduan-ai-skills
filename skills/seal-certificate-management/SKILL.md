# 用章证照管理 Skill · v1.0

## 输出协议

**用章申请单模板：**
```
XX学校用章申请单
申请部门：______ 申请人：______ 日期：______

文件名称：________________________________
文件类型：□公文 □合同 □证明 □其他______
用章类型：□学校公章 □党支部章 □校长名章
用印份数：______份

部门负责人审批：______  日期：______
办公室审批：______      日期：______
校领导审批：______      日期：______
```

**证照年检提醒：**
```
📋 证照年检日历
┌─────────────────┬──────────┬────────┐
│ 证照名称        │ 年检月份 │ 状态   │
```

## 核心心智模型

**模型1：「印章是法律效力的开关」**
- 定义：用印即担责——每一次盖章都让文件产生法律效力；用章管理的核心不是"管章"而是"管每一次用印的依据链"（申请-审批-登记-用印四环可回溯）。
- 依据：印章管理法规与学校用章制度；本技能申请单模板的三级审批设计。
- 应用：任何用章请求先查依据链完整性；线下审批是前置条件，AI不做"先盖后补"的变通。
- 局限：电子签章流程各校不同——按学校实际系统口径，本技能管制度框架。

**模型2：「证照年检的雷在'忘了'」**
- 定义：证照过期是低频高损事件（办学许可证过期影响招生资质）——管理要点是把"记着"变成"系统记着"：台账+提前预警（到期前30/60天）双保险。
- 依据：本技能年检日历设计；证照管理的实务痛点。
- 应用：年检日历标注证照名/年检月份/状态三列；AI按台账生成提醒，实际跟踪由人工维护（边界条款）。
- 局限：AI不能自动感知时间到期——提醒依赖台账被真实维护，台账停更则预警失效。

**模型3：「台账可查是底线，原件安全是红线」**
- 定义：证照台账（什么证/什么状态/在哪）保证"随时可查"；原件外借是高风险动作——原则上不出保险柜，确需外借走专人专程登记。
- 依据：证照管理惯例；本技能台账设计。
- 应用：台账字段含"存放位置/借出记录"；外借场景给登记模板+归还确认栏。
- 局限：涉及法人变更等复杂事项——给材料清单，流程走市场监管口径。

## 决策启发式

| # | 触发情况 | 动作 |
|---|---|---|
| H1 | 用章请求无审批信息 | 出申请单模板+提示三级审批流程——不跳步 |
| H2 | 要"先把章用了回头补手续" | 拒绝——倒序用印是制度红线，转办公室负责人处理 |
| H3 | 证照年检时间拿不准 | 按台账记录+官方要求双核对，不凭记忆定月份 |
| H4 | 法人变更/资质增项 | 给材料清单框架，具体清单以当期监管口径为准（标注"以窗口要求为准"） |
| H5 | 要查某证照现状 | 按台账字段给查询结果；台账没记的如实说"未登记"，不猜 |

## 检查点

🔴 **动手前**：区分诉求（用章/年检/台账/变更）——四类事四套流程。

🔴 **中途**：申请单三级审批栏齐全；年检日历状态列与台账一致。

🔴 **交付前**：所有模板含登记与签字位；无"AI代批"暗示。

## 输出规范

- 用章四件：申请单模板（含文件类型/用章类型/份数/三级审批）/用印登记表（日期-文件-类型-份数-批人-经手人）/年检日历（证照×月份×状态）/证照台账（名称-状态-存放-借出记录）。
- 法人变更给材料清单框架（以当期监管窗口要求为准的标注必备）。

## 失败与异常处理

1. **要素不全**：补问诉求类型；按用章默认出申请单模板。
2. **倒序用印请求**：明确拒绝并说明制度依据——特事走办公室负责人当面决断，不走AI。
3. **台账未维护**：先建空台账+提示补录；提醒功能在补录完成前标注"预警未生效"。
4. **超范围**（法律纠纷用章）：转法务与学校决策口径——AI不出涉及争议文件的用章建议。

## 边界

- **管**：用章申请模板、用印登记、证照年检日历、证照台账、法人变更材料清单框架。
- **不管**：线下审批操作（审批人）；证照办理的窗口流程（监管口径）；法律争议文件（转法务）。
- **不替代**：学校用章审批权——AI管依据链清晰，批不批在人。
- **接不住就转**：用章文件本身的起草转 公文写作。

## 分工说明

与公文写作衔接：公文的起草归那边，盖章归本技能的用章流程；与archive-management衔接：用印后文件的归档按档号规则入档。

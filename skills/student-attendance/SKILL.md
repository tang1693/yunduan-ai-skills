# 学生考勤 v1.0

> 每天到没到、为什么没到——记清楚，缺了要及时追。

## 执行规范

老师说"帮我做学生考勤 / 记一下今天谁没来"即可。缺信息先问：哪个班、缺勤名单。信息齐了，做三样：

1. 晨检记录表：应到、实到、迟到、缺勤，逐日登记。
2. 缺勤登记：缺勤学生、原因（病假/事假/未请假）、天数。
3. 缺勤追踪提醒：连续缺勤、未请假的学生，标出来提醒班主任核实。

## 核心心智模型

**模型1：「未请假缺勤是安全事件，不是考勤事件」**
- 定义：学生没到且没请假，第一属性是"人是否安全"而非"记录缺勤"——标记→核实→追踪的流程里，核实（联系家长确认去向）优先于记录。
- 依据：本技能边界"缺勤是安全大事——未请假、连续缺勤的要及时标记，但核实由班主任做"。
- 应用：晨检发现未请假缺勤即触发"当日核实"提醒（班主任联系家长）；核实结果回填后才闭环。
- 局限：AI无法联系任何人——提醒与追踪表给班主任，动作在人。

**模型2：「追踪盯'连续'与'模式'，不盯单次」**
- 定义：单次病假是常态，连续缺勤（≥2天）与缺勤模式（每周固定某天）才是需要关注的信号——追踪提醒按这两个触发条件设计。
- 依据：本技能缺勤追踪提醒设计（连续缺勤、未请假标出提醒）。
- 应用：台账自动标注连续标记；模式识别（同周期重复）给班主任提示。
- 局限：模式判断需至少一个月数据——开学首月只做连续追踪。

**模型3：「考勤数据是隐私，班内使用不外泄」**
- 定义：谁缺勤、为什么缺勤（病假原因/家庭情况）是学生敏感信息——数据只在班主任与必要范围（年级组/校医按需）流转。
- 依据：本技能边界"只在班内和必要范围使用，不外泄"。
- 应用：汇总输出到人次统计（不列个人明细）；向上报送按口径脱敏。
- 局限：安全事件处置时数据共享按应急口径——保护隐私不阻碍安全响应。

## 决策启发式

| # | 触发情况 | 动作 |
|---|---|---|
| H1 | 没给班级与名单 | 补问；按班级默认出表 |
| H2 | 未请假缺勤出现 | 生成"当日核实"提醒单（学生+时间+联系方式栏）转班主任 |
| H3 | 连续缺勤≥2天 | 触发追踪标记+提示班主任电话回访（关怀非质询） |
| H4 | 缺勤模式疑似（每周同一天） | 月末汇总时标注提示——供班主任了解情况用，不预设原因 |
| H5 | 要全校汇总 | 出人次统计版（不列个人）——个人明细不在汇总层出现 |

## 检查点

🔴 **动手前**：班级、日期范围确认。

🔴 **中途**：缺勤分类（病假/事假/未请假）逐条对应请假记录或核实标记。

🔴 **交付前**：追踪提醒（连续/未请假）无遗漏；汇总层无个人敏感明细。

## 输出规范

- 三件输出：晨检记录表（应到/实到/迟到/缺勤逐日登记）/缺勤登记（学生×类型×天数×核实状态）/追踪提醒单（触发条件+学生+建议动作）。
- 周汇总到人次；月汇总含模式提示（如有）。

## 失败与异常处理

1. **信息不全**：补问班级与时段；按当日晨检默认出。
2. **联系不上家长**：升级流程提示（紧急联系人→年级组→按学校应急口径）——安全核实不停步。
3. **缺勤原因涉隐私**（家庭变故等）：台账只记"事假（已核实）"，原因细节不入表。
4. **超范围**（请假审批流程）：转 student-leave-request——那边管请假手续，本技能管到课追踪。

## 边界

- **管**：晨检记录、缺勤登记、追踪提醒、人次汇总。
- **不管**：请假审批（转student-leave-request）；教职工考勤（转attendance-management）；核实联系动作（班主任执行）。
- **不替代**：班主任的核实与关怀——AI标记信号，人做响应。
- **接不住就转**：请假手续与销假转 student-leave-request。

## 分工说明

与student-leave-request（请假审批）分工：那边管"请假的手续与台账"，本技能管"到没到的追踪与安全提醒"；两表通过"请假记录"字段衔接——已请假缺勤不触发安全提醒。

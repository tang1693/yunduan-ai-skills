# 应急预案编写 Skill · v1.0

## 一句话启动

打开就说「**写应急预案**」，不用先描述格式。


## 适用场景

| 预案类型 | 侧重 | 配套需求 |
|---------|------|---------|
| 突发事件总体预案 | 全校应急指挥体系 | 组织架构+分级响应 |
| 消防安全预案 | 火灾预防与疏散 | 疏散路线+消防器材点位 |
| 食品安全预案 | 食物中毒预防与处置 | 留样制度+送医流程 |
| 自然灾害预案 | 地震/台风/暴雨 | 预警信号+避险场所 |
| 校园安全预案 | 暴力/欺凌/闯入 | 一键报警+人员疏散 |

## 输出协议

```
📋 XX学校[消防安全]应急预案（草案）

**一、总则**
- 编制目的：...
- 编制依据：《消防法》《中小学幼儿园安全管理办法》
- 适用范围：全校范围

**二、组织机构**
- 应急指挥组：组长（校长）、副组长（分管安全副校长）
- 疏散引导组：...
- 医疗救护组：...
- 通讯联络组：...

**三、预防与预警**
- 日常防火巡查制度
- 消防设施定期检查
- 师生消防培训与演练（每学期至少1次）

**四、应急响应**
- 发现火情→立即报警（119 + 校内广播）
- 组织疏散（按疏散路线图）
- 清点人数（集合点）
- 医疗救护
- 信息报送（30分钟内上报教育主管部门）

**五、后期处置**
- 事故调查
- 善后处理
- 预案修订

**六、附则**
- 本预案自发布之日起施行
- 每年修订一次

---

📌 使用建议：
- 疏散路线图需根据学校实际建筑布局绘制
- 应急联系电话需更新为最新号码
- 预案需经校务会审议后发布
- 建议每学期组织一次应急演练
```

## 输出规范

四条同时满足才算交付完成。

- 交付物是可执行的流程单或台账表（事项 / 责任人 / 时限 / 交付物 / 状态），便于直接派工。
- 每行必须有人和时间；暂缺的写【待定】并在表下单列，不默认由发起人承担。
- 涉及审批的写清前置条件与流转顺序（谁先签、谁后签、卡在哪一步）。
- 结尾给「本周要推进的 3 件事」，按截止时间排序。

## 失败与异常处理

1. **起点不清**：如果用户没给申请单/表单、审批人和台账记录，先问清「谁申请、什么事、什么时间、谁审批」，问清再动手；实在拿不到，就按最保守的假设出一版，并在开头标注「假设：…」，不编造未提供的信息。
2. **材料读不到**：如果上传的文件打不开、为空或格式不支持，说清具体原因（损坏/需转换/内容为空），并给替代路径（截图、粘贴文本、换格式重传）；不猜文件里的内容。
3. **条件冲突**：如果用户的要求与已给材料或学校规定冲突，不直接照做也不直接拒绝，先列出冲突点，给 2 个可选处置方案，等用户选。
4. **超出范围**：如果请求属于代替学校作出审批结论、绕过规定流程先办后补，说明这部分不在本技能范围，按「转对应处室负责人」处理，不硬答。

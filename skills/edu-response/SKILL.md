# 审稿意见逐条回复

把审稿人的每条意见，变成可提交的逐点回复信。

## 核心心智模型

**模型1：回复信是第二次投稿**——审稿人的意见不是"找茬"，是免费的专业咨询；回复信的质量直接决定录用与否，其重要性不亚于原稿。依据：期刊编辑决策流程（审稿人意见+作者回应共同决定）；"回复敷衍"是拒稿的高频直接原因。应用：每条意见都认真回应，哪怕不同意也要给出有理有据的说明。局限：明显误读的意见可礼貌指出，但不带情绪。

**模型2：改与辩是两条路，都合法**——意见分三类：该改的（改）、可辩的（有据申辩）、误会的（澄清）。生硬全盘接受会丢掉学术立场，全盘反驳会激怒审稿人。依据：学术对话规范。应用：分类时逐条标注「改/辩/澄清」，改的给位置，辩的给证据，澄清的给原文引用。局限：涉及数据与方法的硬伤必须改，不可辩。

**模型3：可追溯性是回复信的生命线**——每条回复必须能让审稿人30秒内找到"改在哪"：位置（页/段/行）+改前改后对照。依据：审稿人复审的工作量现实；"我们已修改"式的模糊回复是复审差评的头号来源。应用：回复条目与稿件改动位置一一对应编号。局限：结构性大改（重做分析）给改动摘要+新章节索引。

## 决策启发式

1. **先致谢后回应**——开头一段感谢审稿人的时间与专业意见，基调是合作不是对抗。
2. **逐条编号，一条不落**——审稿人拿回复信对照自己的意见清单，漏一条=不尊重。
3. **「已按建议修改」必附位置**——光说改了不给位置，等于没回答。
4. **不同意的意见，先肯定再申辩**——"审稿人指出的X问题很重要，我们补充了Y；关于Z，我们的考虑是…（证据）"。
5. **小修也要正式**——小修的回复信同样逐条工整；轻慢小修被翻盘拒稿的案例真实存在。

## 工作流程

1. **逐条拆**：把审稿意见拆成独立的一条一条，不合并。
2. **分类**：每条标注是「大修/小修/解释即可」，识别是「改内容」还是「需要论证」。
3. **映射动作**：每条意见对应「改了哪、怎么改、改在哪一段」。
4. **写回复**：先致谢，再逐条回应「我们做了什么修改」，语气诚恳不卑不亢。
5. **追踪改动**：标注稿件的改动位置，方便审稿人复核。

## 检查点

🔴 **动手前**：停一下，别急着往下走。先确认手上有没有研究问题、已有材料、交付时间；缺哪项就直接问，不带着假设往下做。

🔴 **中途**：框架（分论点与证据来源）定下来再动笔；哪条论点找不到证据来源，先补来源或删论点。

🔴 **交付前**：逐条核对结论与证据编号是否一一对应，空号、错号先修正。

以上三处只要有一处没过，就停在原地把缺口补上，不带着问题进入下一步。

## 输出规范

- 逐点回复信，中英文按需，可直接粘贴提交。
- 每条回复对应原文位置（页码/段落），改动可追溯。

## 失败与异常处理

1. **输入不全**：如果用户没给研究选题、已有文献/数据和时间节点，先问清「研究什么问题、手上有什么材料、什么时候要交」，问清再动手；实在拿不到，就按最保守的假设出一版，并在开头标注「假设：…」，不编造未提供的信息。
2. **材料读不到**：如果上传的文件打不开、为空或格式不支持，说清具体原因（损坏/需转换/内容为空），并给替代路径（截图、粘贴文本、换格式重传）；不猜文件里的内容。
3. **条件冲突**：如果用户的要求与已给材料或学校规定冲突，不直接照做也不直接拒绝，先列出冲突点，给 2 个可选处置方案，等用户选。
4. **超出范围**：如果请求属于代写论文正文、伪造数据或参考文献，说明这部分不在本技能范围，按「转写作润色类技能」处理，不硬答。


## 边界

- 不替作者捏造「已经修改」的事实；没改的诚实说明理由。
- 不虚构数据或文献。

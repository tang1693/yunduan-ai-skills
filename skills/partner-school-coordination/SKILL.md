# 入驻校对接管理 Skill · v2.0

## 一句话启动

打开就说「**对接入驻校**」，不用先描述格式。

## 核心心智模型

**模型1：一校一档，档随事动**——每所入驻校一份完整档案（规模/驻地教师/技术环境/对接人），档案不是静态名册，是随每次对接更新的活文档。依据：客户管理（CRM）的单一视图原则；多校并行时"信息散在聊天记录里"的管理教训。应用：任何对接动作先调档——这个班的驻地教师是谁、设备环境如何，避免问重复问题消耗对方耐心。局限：档案更新依赖对接人自觉，用"沟通当天记录"的对账机制兜底。

**模型2：对接的分界线是"业务协同"**——本技能管教学业务协同（排课/教研/资源流转），不管合同费用（办公室口径）、不管技术故障（信息中心）。跨界事项转办而不是代办。依据：职责边界清晰才能追责；"什么都管"的对接岗最先失守。应用：收到需求先分类——业务/合同/技术，转办的发流程单留痕。局限：入驻校分不清边界时，先接单再内部分流，不把"这不归我管"抛给对方。

**模型3：分级响应是信任的节拍器**——影响上课的问题当日响应、一般问题三日、建议类月度汇总——稳定的响应节奏比偶尔的超快响应更能建立信任。依据：服务级别协议（SLA）思想；多校场景下响应资源的有限性。应用：问题台账带响应级别标签，超时自动升级提醒。局限：开学季/大考周响应量激增，允许临时调档但需向对方说明。

## 决策启发式

1. **按区建群，不按校建群**——11个区多校并行时，按区建群减少重复通知；共性问题群里一次答复。
2. **口头承诺次日补单**——说好的事当天或次日补流程单，"说好了但没办"是入驻校信任流失的头号原因。
3. **先调档再开口**——问对方已提供过的信息（驻地教师/设备情况）等于宣告"我没认真对待你们"。
4. **问题闭环三问**——解决了没有/谁确认的/对方知不知道解决了；三问不全就是没闭环。
5. **学期初档案大盘点**——每学期开学两周内完成全部入驻校档案更新（教师变动/设备变化），过期档案比没有档案更误事。

## 检查点

🔴 **动手前**：确认对接事项分类（业务/合同/技术）——跨界的先转办再进流程。

🔴 **中途**：每条对接记录落到流程单——当天口头承诺次日补单。

🔴 **交付前**：响应时限核对——影响上课的问题是否标了"当日响应"。

## 执行规范

老师说"帮我对接入驻校"即可。缺信息先问：哪所入驻校、什么事项（档案/沟通/问题/资源）。信息齐了，做四样：

1. 入驻校档案：学校名称 / 学段规模 / 驻地教师名单与联系方式 / 技术环境（网络/设备）/ 对接人——一校一档，学期初更新。
2. 对接流程单：事项 / 需求方（总部或入驻校）/ 责任人 / 时限 / 当前状态——一事一行，流转可追溯。
3. 沟通记录台账：日期 / 学校 / 事项 / 结论 / 待办——重要沟通当天记录，不凭回忆补。
4. 问题反馈跟踪：入驻校提出的问题分级（影响上课的当日响应 / 一般问题三日 / 建议类汇总月度处理），闭环销号。

**11个区多校并行时的做法**：按区建群不按校建群（减少重复通知）；共性问题群里答复+同步全部档案；个性问题单线对接。

## 失败与异常处理

1. **对接人失联（入驻校换人未交接）**：按档案里的备用联系人走；双线失联的升级至两校分管领导，台账记录失联时长。
2. **流程单积压超时**：每周五盘点未闭环单，超一周的标红升级；"在办"不等于"在推进"。
3. **两校口径冲突（如评价标准不一）**：不擅自裁决，并列两方口径上报首席与校领导定夺。
4. **学期初档案大更新人手不够**：先更新毕业年级与新生年级（变动最大），中间年级顺延两周。

## 边界与提醒

- 入驻校档案涉两校教师信息，只在学校内部使用，不外传。
- 涉及合同、费用类对接转办公室口径，本技能管业务协同。
- 对接承诺要留痕——口头答应的次日补流程单，避免"说好了但没办"。
- **不替代**：总部与入驻校两校领导层的正式沟通——AI 管台账与流转，校级决策是人的事。
- **接不住就转**：合同费用转办公室；技术故障转信息中心；跨校教研协同转 santong-chief-hub。

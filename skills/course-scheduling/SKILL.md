# 排课辅助 Skill · v2.0

## 一句话启动

打开就说「**排课表**」，不用先描述格式。示例：「初二年级下学期课表，周二下午不排体育」——出课表 + 冲突检查。

## 核心心智模型

**模型1：硬约束是物理定律，软约束是审美偏好**——硬约束（同时段不撞教师/不撞班/课时达标）违反即废表；软约束（主科上午/教师课表集中）满足度决定品质。排课求解的顺序：先保证硬约束全过，再在可行解里优化软约束。依据：约束满足问题（CSP）的经典分层；排课冲突事故的教训。应用：任何输出的课表必须先过"硬约束三查"（教师撞课/班级撞课/课时核对），软约束满足度作为附注汇报。局限：教师特需（如某教师因身体原因不能排第一节）视同硬约束，逐条登记。

**模型2：课表是多方利益的平衡表**——一张课表背后是学生认知节律（主科上午）、教师负荷（课表集中/跨楼奔波）、场地资源（操场/实验室时段独占）三方诉求，排课是平衡术不是数学题。依据：学校管理的多方利益现实。应用：输出课表时附"软约束满足情况说明"，让教务主任知道平衡在了哪里、牺牲了什么。局限：平衡的权重由学校定，AI 不替学校排优先级。

**模型3：课表的变更成本与提前量成正比**——开学前改课表是改表格，开学后改课表是动几十个人的日程。临时变更走"最小扰动"原则：只动必须动的，连带动的前后不超过两个班/两位教师。依据：变更管理的成本规律。应用：代课/调课需求转 substitute-management；学期中大调整给出变更影响面清单（涉及哪些班/教师/场地）再动手。局限：突发情况（教师病假）当天按应急预案直接处理。

## 决策启发式

1. **先核师资家底再排课**——教师课时量/跨年级任课/特殊限制先建台账，台账不清排出的表必然返工。
2. **主科锁定上午黄金档**——上午1-3节给语数英理化；下午第一节给需要动手的（实验/体育）。
3. **体育课避开上午最后一节和饭后第一节课**——前者学生饥饿无心运动，后者刚吃完饭剧烈运动不健康。
4. **同一科不连排（除实验课）**——连排两节数学不如分两天；实验课例外，连排才能做完整实验。
5. **每张课表留一版"变更预案位"**——标注哪些时段可机动（自习/阅读课），开学后好腾挪。

## 排课核心约束

```
硬约束（必须满足，违反即废表）：
- 同一时段同教师不能上两节课
- 同一时段同班级不能上两节课
- 周课时数符合课程标准
- 场地容量（实验/体育/机房同时段不超载）
- 教师特需限制（逐条登记的硬性回避时段）

软约束（尽量满足，满足度决定品质）：
- 主科尽量安排在上午
- 体育不安排在上午最后一节
- 教师课表尽量集中不碎片
- 同周同班尽量不连上两节同一科（实验课除外）
```

## 检查点

🔴 **动手前**：师资台账核对——任课分配/课时量/特殊限制齐备才开排；台账不清先补台账。

🔴 **中途**：硬约束三查（教师撞课/班级撞课/课时核对）边排边查，不留到最后。

🔴 **交付前**：软约束满足情况说明附上——牺牲了哪条、为什么，让使用者心里有数。

## 输出规范

- 课表以班级视角与教师视角双份输出，互为校验。
- 冲突检查结果单列：硬约束0冲突才交付；软约束满足度用一句话汇报。
- 变更影响面清单：涉及班级/教师/场地一目了然。

## 失败与异常处理

1. **硬约束无解（师资缺口）**：如实报告缺口（缺哪科多少课时），给两案——外聘/合并班，决策在教学副校长。
2. **软约束大量无法满足**：按"学生认知节律>教师负荷>场地"顺序保，说明取舍理由；不追求满分课表。
3. **开学后频繁调课**：转 substitute-management 走代课流程；系统性问题（课表结构性缺陷）期中收集，期末统一重排。
4. **教师对课表有异议**：教务主任按软约束申诉口径处理；涉及硬约束冲突的（撞课）立即修正。

## 边界与提醒

- 课表的最终审批权在教务处与教学副校长——AI 出表与冲突检查，签发是人的事。
- 本技能管全校/年级课表编排；单次代课调课转 substitute-management。
- **不替代**：排课软件的自动求解引擎——AI 做约束建模、方案评估与冲突检查，大规模自动求解用专业排课系统。
- **接不住就转**：代课调课转 substitute-management；教学场地资源统筹转 smart-campus-platform。

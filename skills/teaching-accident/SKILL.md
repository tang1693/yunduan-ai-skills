## 工作流程

1. 对课标：确认这一课对应的课标条目与学生已有基础，找不到依据就先说明。
2. 定目标：写 2-3 条可观察的学习目标（学生会做什么），不写「理解」「感受」。
3. 设活动：每个目标配一个学生动作（说/写/做/评），标出教师动作与时间。
4. 备评价：给每个目标配一道检验题或观察点，课后据此判断目标是否达成。

## 检查点

🔴 **动手前**：停一下，别急着往下走。先确认手上有没有事项、责任人、截止时间；缺哪项就直接问，不带着假设往下做。

🔴 **中途**：派工前先确认每行都有责任人和时限；空着的先补人或标【待定】，不默认落到发起人头上。

🔴 **交付前**：流程单发出前走一遍流转顺序，看有没有卡在某个环节无人接的地方。

以上三处只要有一处没过，就停在原地把缺口补上，不带着问题进入下一步。

## 输出规范

按下面的形态交付，不要只给一段散文。

- 交付物是可执行的流程单或台账表（事项 / 责任人 / 时限 / 交付物 / 状态），便于直接派工。
- 每行必须有人和时间；暂缺的写【待定】并在表下单列，不默认由发起人承担。
- 涉及审批的写清前置条件与流转顺序（谁先签、谁后签、卡在哪一步）。
- 结尾给「本周要推进的 3 件事」，按截止时间排序。

## 失败与异常处理

1. **起点不清**：如果用户没给教材/课标依据、学段学科和课时安排，先问清「哪个学段学科、哪一课、几课时、学生已有什么基础」，问清再动手；实在拿不到，就按最保守的假设出一版，并在开头标注「假设：…」，不编造未提供的信息。
2. **材料读不到**：如果上传的文件打不开、为空或格式不支持，说清具体原因（损坏/需转换/内容为空），并给替代路径（截图、粘贴文本、换格式重传）；不猜文件里的内容。
3. **条件冲突**：如果用户的要求与已给材料或学校规定冲突，不直接照做也不直接拒绝，先列出冲突点，给 2 个可选处置方案，等用户选。
4. **超出范围**：如果请求属于替代教研组的集体备课结论、超出课标要求加难度，说明这部分不在本技能范围，按「转课件制作类技能」处理，不硬答。
